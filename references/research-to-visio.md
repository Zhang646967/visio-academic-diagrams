# 科研语义 → Visio能力的映射

下表是本项目的设计策略，功能说明应回到能力条目的官方来源。优先采用完成任务所需的最小功能组合。

| 科研表达需求 | 合适的Visio能力 | 为什么使用 | 必须检查 |
|---|---|---|---|
| 阅读论文的主题层级 | MM01–MM10脑图或基本树形布局 | 编辑父子主题，比随手摆框更易维护 | 树边不是控制流；交叉关系另记 |
| 算法判断和循环 | 基本流程图、CN01–CN07连接与粘附 | 明确条件和返回点 | 循环与终止是否与伪代码一致 |
| 多模块方法框架 | ST01容器、LY01–LY03对齐、ST03图层 | 管理组件边界和审閱信息 | 模块边界有来源，容器成员真实存在 |
| 训练和推理两条路径 | 两页或两组容器，数据/控制边分型 | 避免把学习参数与预测执行混为一谈 | 两视图组件名称和参数共享一致 |
| 变量与公式解释 | 文本、标注、Shape Data、必要的公式对象 | 图中短标签，旁注保持定义 | 下标、符号、字体和导出没有失真 |
| 论文中的方法比较 | 分区/矩阵与统一图例 | 对比相同维度 | 缺失信息不可当成不具备该功能 |
| 引理如何支撑定理 | 依赖图、基础形状、带语义标签的边 | 表现逻辑而非时间执行 | 无循环证明；方向约定明确 |
| 证据如何支持结论 | 证据图、分层布局、注释 | 保留证据类型和局限 | “作者假说”“观察关联”等限定可见 |
| 实验安排和责任 | 泳道、阶段、时间线 | 区分角色、时间和数据对象 | 时间线长度有尺度；泳道不是结果等级 |
| 大规模可维护论文图 | 主控形状、模具、模板、形状ID、数据关联 | 统一复用，便于追踪修订 | 继承修改、刷新是否改变已定版图 |
| 审稿来回修改 | 图层、评论、源稿/投稿稿分离 | 保留审查历史和修改说明 | 公开图无隐私、草稿标记或外部数据 |
| 最终论文插图 | EX01–EX03、期刊配置、最终尺寸检查 | 分离可编辑、审阅、投稿三种产物 | 真实字线、嵌入字体、裁切和允许格式 |

## 将过程表转换为图不是理解论文
Data Visualizer能利用节点ID与下一步ID生成结构[M23]，但不会替用户判定研究逻辑。
先完成paper-model及figure-plan，再考虑表格导入。不要让Excel行顺序决定算法顺序。

## 每次操作必须说明的内容
动作针对哪个节点/边；为什么需要这个能力；许可证和平台前提；具体菜单或动作；数值；可观察检查点；失效时的已核验替代。
仅有高级目录入口时先检索，不要为了让回答显得完整而给虚构路径。
