# UML / DFD / ER / BPMN：专用记法门禁

本包提供选择与官方入口，不声称已经实现这些标准的完整语法和语义检查。

| 图种 | 应表达什么 | 官方入口与限制 |
|---|---|---|
| UML | 按具体图种表达结构或行为，而非任意框箭头 | [M28]，先确定活动图、时序图、类图、组件图等，再读对应教程 |
| DFD | 处理、数据及其流动 | [M27]；不能把控制流程图换个标题当作DFD |
| ER/数据库模型 | 实体、关系、基数等数据结构 | [M24]；不要承诺所有版别均可反向工程数据库 |
| BPMN | 业务过程建模的专用符号及连接语义 | [M29]；按版本、授权和地区分别核验 |

## BPMN可用路径摘要
桌面可在File > New搜索BPMN Diagram；连接器需要区分sequence flow、message flow与association。需要时在Process > Diagram Validation > Check Diagram检查图形规则。[M29]
该校验不证明属性值或业务含义正确；网页也不具备同样的校验操作。不要为了配色把一种连接线改得像另一种。

## 出口规则
要求“严格符合某标准”时，还需读取标准维护者发布的相应版本，例如OMG对应规范，并建立符号映射和合规检查清单。未读取时交付“按官方Visio教程制作的草案”，不能用“通过标准认证”等措辞。
未知授权时先设计逻辑模型，不绕过许可证或推荐破解。使用基本矩形实现的替代草图必须明确它不是专用记法的完整替代。
