# 图关系的语义合同

本项目使用两层类型：paper-model里的学术关系，以及figure-plan里的展示关系。二者通过稳定ID关联。

| 学术关系 | 展示关系 | 默认表达 | 不能暗示 |
|---|---|---|---|
| contains / is_a | hierarchy | 父子连线，通常不加方向箭头 | 执行顺序、因果 |
| precedes / controls | control | 有方向的流程箭头，分支写条件 | 某动作导致某统计效果 |
| uses / produces | data | 数据方向及内容标签 | 程序一定顺序执行 |
| depends_on | dependency | 按声明的方向表示前提依赖 | 时间先后；证明必须是时间过程 |
| associated_with | association | 无箭头关联线和关系说明 | 原因或干预效应 |
| causes | causal | 有向边，并显示假说/证据/假设状态 | 只因有箭头就已证明因果 |
| supports / contradicts | evidence | 标注“支持/冲突”等关系 | 数据已排除所有替代解释 |
| communicates_with | message | 有向消息/协议标签 | 物理线缆位置 |

对于depends_on，本包约定学术from是依赖方、to是被依赖方；图中边也保持同向。需要画“前提→结论”时用figure-plan的 reverse_relation=true明确反向映射，并在图例中写清；不能静默反向。
contains约定from是父主题、to是子主题。is_a约定from是具体类、to是上位类；投影成树时需显式reverse_relation=true。
associated_with是语义无向关系，即使JSON存了from/to，默认仍为无箭头线。

## 图种结构约束
脑图：层级边构成单根树；关联边可以另外存在，但必须有标签并与层级边区别。关联边不参与父子树校验。
概念图：允许多父关系和跨组关联，不强制树，也不默认DAG。
流程图：判断节点至少两个不同出口，循环允许；图上能到达End并不能证明算法一定终止。
证明图：依赖关系需无环；节点包括假设、引理、定理；证明正误仍需数学审阅。
因果DAG：因果子图需无环；存在反馈的动态系统要改用动态因果/系统关系图，而非把有环图称作DAG。
数据管线：方向由数据产生和使用决定；训练、推理、在线和离线阶段要区分。

## 图例和图注
“实线=原文明确，虚线=作者假设/AI建议”只有在图注确实这样定义且读者能区分时才成立。
不要仅靠颜色或形状传达支持状态。状态词可以留在阅读版标签或审阅表；投稿版是否保留由图的目标决定，但不允许增强原结论。
